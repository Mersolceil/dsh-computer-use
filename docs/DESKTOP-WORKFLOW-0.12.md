# 0.12：减少往返、浮窗授权和桌面图片历史（alpha发布说明）

用户在0.11实际试用仍遇到频繁授权、目标遮住DSH，以及短任务费用偏高。本轮查到的代码原因包括：任务授权仍可被Agent漏用；重复设置mode会销毁授权（0.12已改幂等）；每个动作和之后的截图要分别经过模型；桌面图片没有接入浏览器的整理策略。API费用须依据提供方实际用量判断，不能把费用直接归因于缓存失效。

## 新流程

`cu_desktop_start({application,purpose,control})`在一个工具调用内：后台打开或复用应用→选择唯一可见普通窗口→申请一次有界任务授权→开本地预览→返回首图。窗口有歧义则返回已有window_id列表，等待选择，不盲选；特殊应用/非常规路径的启动仍可能额外授权。control仅在任务需要输入时设true，纯观察设false。

随后用`cu_desktop_step({action,screenshot_id,...})`执行**一个**依据截图的key/type/pixel_click/scroll，并在同一工具结果返回事后图，不再另走一个模型回合取图。整段已授权的中文和换行放在一次type中，不逐字调用。窗口内容有变化、截图过期、敏感行为或真实失败仍会阻止执行；输入已发生而事后截图失败时明确标记never_replay_whole_step，禁止把整个步骤重做。

相同mode和相同任务目的/窗口的authorize不再重新申请，也不会偷偷延长原授权时限或次数。普通可信应用的一段任务仍需用户第一次明确批准，敏感、整屏、退出等另外确认。默认5分钟/100次内部操作，15分钟/200次硬上限；turn结束即撤销。start/step中的内部操作也计入限额。

## 授权不必切回被遮住的DSH

新增原生置顶、非激活授权面板作为本插件确切在途请求的DSH `approval/request` 应答器。它只收集本次人的点击，回到原来的宿主审批服务写审计；不是自动允许，也不更改全局ask/never或系统TCC。拒绝、关闭、超时、取消、错误ID/无效回答均不准执行。`nativeApprovalEnabled:false`可回到原DSH应答器。

此前的本地图片预览保留；两者都不是嵌入DSH前端的Codex式面板。原生真实鼠标/键盘动作仍可能短暂把目标带到前台。本轮新增：若输入前DSH在前台，投递后请求把焦点还给同一PID/启动代次的DSH；用户期间切去其他应用则不抢回。macOS若拒绝激活，仍记录真实结果，不宣称后台任意操作已实现。

## 减少重复图片与上下文

- 默认窗口图最长边1024，允许按阅读需要配置640–1600。降低分辨率可能影响小字，不能承诺所有界面都适合最小图。
- 图片复用只认**完全相同的PNG字节**，并确认同Agent的既有结果已提交、旧图仍在可见模型surface且未offload。粗缩略图仅作输入前检查，绝不当成缓存依据。复用结果指向已有图，同时仍刷新截图票据、几何和输入约束；并非不截真实窗口。
- 桌面Native结果单独投影，超过6张时才批量卸载旧图，保留最近2张，原日志和附件不删除。阈值前不改旧消息，减少逐步破坏缓存前缀。用户新输入及宿主压缩期间延后；不处理用户上传图片和身份不明/PTC图片。缺宿主image/offload投影时安全跳过。
- `cu_desktop_context_status`给出真实图片event_seq索引；`cu_desktop_image_recall`据此回查，禁止猜ID和把旧图当新图。索引保留最近64条图片记录，不能声称无限历史。没有模型摘要调用。

**API前缀缓存和历史裁剪是不同事情。** DeepSeek默认启用上下文缓存，实际命中由`prompt_cache_hit_tokens`、`prompt_cache_miss_tokens`报告；前缀相同只是条件之一，不能保证每次命中。[DeepSeek官方说明](https://api-docs.deepseek.com/zh-cn/guides/kv_cache/)。offload旧图也会改变此前消息，从最早改动处打断缓存复用，所以本轮采用批量而非每步整理。不能把本地图片复用计数冒充provider cache hit，更不能把减少工具调用直接换算成人民币节省。

## 本轮证据与未完成项

- 9项相关单元通过：组合流程、授权幂等/范围、事后截图失败不重做、图片精确复用/身份/可见性、批量整理及保留。另1项运输协议测试确认错误ID和取消后的迟到允许无效。
- 真实DSH本地服务检查通过：原生面板传输用脚本替身，验证真实waterfall的prepend接管和never先行拒绝；补查preview=false授权返回通过真实ToolRuntime的lossless JSON校验，3对审计一致。7个合成图片结果offload5、保留2，回查、恢复、pending输入延后、宿主投影缺失安全跳过及静态上下文一致均通过。不是人工图形批准，也不是付费模型测评。
- 首次附件检查使用unit里的1×1伪PNG，被真实附件库拒绝；改用合法的自制64×64测试PNG后通过，失败保留。
- 新原生助手编译签名通过。桌面补查preflight返回SESSION_LOCKED，编辑器/输入未开始。检查脚本文本替换误把合成授权面板检查放入锁屏分支，面板未出现即失败；已修成锁屏立即退出，静态检查确认合成面板只在编辑链通过后进入，未继续GUI重试。原生面板入口也补会话不可交互时立即取消。

解锁后的最终代表流程通过：真实DSH ToolRuntime/ApprovalService/LocalAttachmentStore下，start + 4次step + revoke共6工具调用，独立临时编辑器确认新建1、mouseDown1、中文/emoji/换行逐字一致、保存1；5次前台检查，4次输入后都返回真实DSH。交付4张图，1次完全相同图复用。窗口部分越界与本地预览仍可用。2次脚本批准分别为非常规测试应用路径和任务范围；普通可信应用的一次范围批准另由单元覆盖，不把脚本批准说成人工点击。

已实际查看新原生授权浮窗，用合成无控制请求验证真实“拒绝”按钮，收到相同请求ID的rejected，未授权任何个人应用动作。完整人工“允许”流程没有验收。新序列化缺陷根因为preview=false仍输出local_preview:undefined，已经改成字段缺省；失败后的真实工具接口检查通过。首次新增检查误把isError=false预期为undefined，修正断言后通过，未更改检查来绕过lossless约束。

0.12为公开alpha源码版本，当前设置见DESKTOP-CONTROL.md，验证范围见VALIDATION.md。实际Obsidian、本版本真实模型自主任务、每笔费用变化和动画页面控制仍未验收。全窗口粗图像校验在视频/轮播页面仍可能频繁拒绝，本轮未放宽它，也不能把用户界面报告视为我们对视频任务的独立验收。所有本轮付费API/模型调用为0；CU仅查看用户指定DSH界面及用量，未读取凭据、原始会话文件或个人笔记，没有额外完整回归。
